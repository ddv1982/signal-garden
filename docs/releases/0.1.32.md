# Release 0.1.32 — put every screen in the garden and record what cannot be regrown

Move the whole app inside the painted world instead of beside it, give the icon the garden's own iconography, and write down which art the repository can regenerate and which art is the only copy that will ever exist.

## Highlights

- Puts home, archive, settings, and onboarding inside the same blurred garden world the canvas already painted, with frosted panes over it rather than flat surfaces beside it.
- Rebuilds the mobile garden chrome from three stacked rows into two, moving lens controls into a bottom sheet that respects the safe-area inset.
- Replaces the `SG` monogram with a sprout drawn from the garden's own plants, carrying an amber signal point taken from the lantern in the art. The same mark now serves the browser tab, the app icon, the Safari mask, and the top bar.
- Adds `prefers-reduced-transparency` as the escape hatch for pane blur, swapping every `backdrop-filter` for an opaque fill when the reader asks for less transparency.
- Gives archive cards a growth meter so a seed's stage is legible without opening it.
- Re-derives the dark backdrop from its master instead of transcoding an intermediate JPEG, and moves the last four JPEGs to WebP.
- Records art provenance in `art-source/provenance.json` and checks it in CI, after finding that both light backdrops have no master anywhere in history and are permanently irreplaceable.
- Fixes nine first-paint theme tests that silently stopped stubbing the entry module whenever the dev server had seen a file change.

## Lore

Constraint: The garden art, the lens journey model, and the storage seams were all settled. This pass could move the chrome into the world and account for the art, but it could not repaint the world or change what a seed is.
Rejected: Move `art-source/` to Git LFS | Measured over the whole history, the masters are 20.7% of it across 7 blob versions, while regenerable screenshots are 43% across 51. LFS caps bandwidth at 1 GB a month over every clone, fork, and CI checkout, and when exceeded it serves pointer files in place of images. That is the wrong failure mode for the only art that cannot be regenerated.
Rejected: Recompress the masters losslessly | Lossless WebP shrinks them 24.6% pixel-identical, but committing the smaller files adds their bytes while the originals stay reachable, so the clone grows to make the working tree smaller.
Rejected: Delete every superseded backdrop | Two of them reproduce byte for byte from committed masters, so the recipe is the archive. `background-v3.webp` has no master at any commit on any branch, and art that cannot be regrown is not cleanup.
Rejected: Restore the `SG` monogram | The complaint was a muddy gradient orb introduced by this branch, not the tile it replaced. Fixing that regression was separate from asking what an icon for a garden of signals should be.
Rejected: Disable `reuseExistingServer` for local runs | It would have turned the nine failures green while making every local run pay for a cold dev server, and it would have left the stub still silently not matching.
Rejected: Add streaks or badges to the archive | The archive is where someone reads what they noticed. Counting the days would make missing one a failure, which is the opposite pressure to the one this app is for.
Confidence: high
Scope-risk: medium
Directive: Let the world show through every pane, give the tab the same plant the garden grows, and never lose art the repository cannot grow again.
Tested: `pnpm typecheck`; `pnpm lint`; `pnpm format:check`; `pnpm test` (118 tests, 19 files); `pnpm build`; `pnpm e2e` (62 passed) on each branch; `pnpm art:audit` (9 pinned, 1 regenerated and matched with all three branches applied); the first-paint tests run against one dev server held in a known-dirty state, where the old glob matched zero requests and the new predicate passed all nine; the dark backdrop re-derive measured at 33.71 dB against its master versus 31.78 dB for the file it replaced, then rendered in dark mode on the Phaser canvas and behind onboarding; icon candidates rasterized and compared at 16, 32, and 180 px.
Not-tested: The `backdrop-filter` cost was measured in headless Chromium on a virtual machine using software rasterization and CDP CPU throttling, which is not a substitute for a real low-end Android device. No physical iOS or macOS Safari was available, so the pinned-tab mask icon was verified by rasterizing the SVG rather than on a device. GitHub Actions production deploy and release publishing have not run for this tag yet.
